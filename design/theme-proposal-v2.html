1为什么再来两稿

  • v1 的 A / B 其实是同一套语言：冷中性底 + 高饱和彩色实心主按钮 + 彩色投影，只差色相，看着都像通用 SaaS 后台。
  • 这稿刻意拆开两个变量：--primary-bg（主操作填充）与 --signal（选中 / 焦点 / 链接的状态色）。两者不等，才有新的层次。
  • C 石墨 把主操作交给无彩色，D 柔雾紫 把主操作交给渐变；一个更克制，一个更柔和，都不是「再换个蓝绿色」。

2C · 石墨极简（无彩主操作）

  • 浅色中性近白 #fafaf9、深色纯黑 #0c0c0e，几乎不带色偏；主按钮浅色近黑 #18181b、深色纯白 #ffffff，靠明度反差而不是彩色抢眼。
  • 琥珀 #e0863c / #f0a055 只做状态色：选中项、焦点环、左指示条。圆角收敛回 6 / 10 / 12，边框更明确。
  • 适合嫌 A/B「颜色太跳、太像网页」的情况。代价：品牌青绿几乎退场，图标与 selection-bar 的硬编码色必须同步改。

3D · 柔雾紫（渐变主操作）

  • 中性带极淡紫：浅 #f7f7fc / 深 #12121e；主按钮是 紫→蓝线性渐变，柔光投影更散，选中态用淡紫底 + 紫描边。
  • 圆角放大到 9 / 14 / 16，卡片操作项改药丸形，整体比 A 软一档，不冷不硬。
  • 适合嫌 A/B「太硬、太冷」的情况。代价：离现有青绿品牌最远，渐变在低色域屏和截图里层次会变弱。

4共通项与落地

  • 5 套都保留：按钮四阶梯、卡片操作项常态可见、选中卡片 3px 状态色左条、字号与三栏尺寸不变。
  • 新增变量共 4 个：--on-accent / --accent-shadow / --signal / --primary-bg；未显式声明的方案会自动补齐后两个，旧样式不会缺值。
  • 落地仍只动 tokens.css 与 components.css 的按钮、chip、卡片操作项、选中态；不改 JS，不碰主题切换逻辑。
